## 2. New findings raised by this test

| # | Severity | Finding | Status |
|---|---|---|---|
| N1 | Medium | `db_catalog` omitted the `og.project` table entirely (295 rows, used by `list_projects` and `search`), listed the tables `search_concept` / `search_term` under **functions**, and the four curated tables' column lists lacked `search_text` | **Fixed** — project added, search tables moved to tables, `search_text` listed |
| N2 | Medium | `list_gaps` returned **everything** — 30+ near-identical TRL rows for one sector, several hundred in total, in one response; a client asking "what is missing?" got a wall of text | **Fixed** — `limit` (default 100, cap 1000) plus guidance to narrow by sector/field/reason_code. The `/gaps` page reads the dataset directly so it still shows every row |
| N3 | Low (data) | The corpus stores source documents twice: **36** documents. First reported as only the NETL MVA 2017 manual (`…-8b88bb67.md` slug title and `…-f43dd9c1.md`, same body); a corpus-wide scan found **12** with identical urls (NETL MVA and Cost & Performance Baseline Vol 1, IEA CCUS, DOE/NPC Ch 8, DOE SAF pathways, Global CCS CO₂ shipping, NSTA wells, three arXiv papers, two LEMIGAS papers — 1,702 duplicate chunks) and, once the url key normalised arXiv version suffixes, **24** metadata-only records filed beside the full text of the same paper. Live `search` returned both copies in one result set | **Fixed 2026-11-23 (second pass, owner-approved)** — the redundant copy removed in each pair, keeping the full text (or the proper title and the more complete extraction); `agent/urlnorm.py::url_key` drives both the collector's refusal and the `tools/build.py` gate (decision 40), and the MCP instructions and document-tool descriptions state the invariant. Live: 253 documents / 11,876 chunks, one copy per result |
| N4 | Low | The loader's publish summary reported `vectors` as the vectors *carried* from the baked index (16,902), not those *stored* (15,410 — restricted passages never enter Neon) | **Fixed** — the summary counts rows with an embedding after the load |
| N5 | Low (test) | `tests/test_web.py::test_gaps_page_shows_register_entries_without_a_card` depended on the header an earlier test left on the module-scoped client: it 401'd when run alone | **Fixed** — the test authenticates explicitly |
| N6 | Operational | The local Docker build ran out of disk mid-image (`write …/workerd: no space left on device`); `deploy/local-images.sh` reported exit 0 because the output was piped to `tail` | **Resolved** — 18.2 GB of stale build cache pruned; both images built and shipped |

## 3. What changed in the surface as a result

- `list_gaps(sector, field, reason_code, include_no_card, **limit**=100)` — bounded response.
- `db_catalog()` — `og.project` added, `search_concept`/`search_term` listed as tables, `search_text`
  added to technology/vendor/equipment/project.
- Server **instructions**: routing now covers `compare_technologies(technology_ids=…)`,
  `list_documents`, and `get_register_entry`; a "how search ranks" paragraph explains concept
  coverage and rare-term qualifiers; a "reading text" paragraph explains `get_document` paging and
  `text_included: false`.
- `tools/load_postgres.py` — publish summary reports stored vectors.
- `agent/web.py` — `/gaps` reads the dataset directly instead of the capped MCP tool.
- `collectors/common.py` — a document is stored once per **source URL** (`url_key` ignores scheme,
  case, `www.`, a trailing slash and the fragment), not once per body digest; `agent/library.py`
  gains `duplicate_documents()` and `tools/build.py` refuses a build that has one.
